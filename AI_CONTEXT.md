# DW Manager v2 implementation context

Read `AGENTS.md` for the required version policy. This file maps implemented behavior; verify source and tests when editing. V2 is a major schema/UI change from combined Sandboxes to independent Environments and Sites.

## Contract

- Workspace file: `dw-manager.json`, `{schemaVersion: 2, environments: Environment[], sites: Site[]}`.
- Environment: `{id,name,hostname,username,password,version}`, all strings.
- Site: `{id,name,cartridgesPath}`, all strings; path is a colon-separated ordered string, optionally empty.
- IDs generated by `crypto.randomUUID()` on creation; edits/renames retain IDs. IDs must be nonempty strings and unique across both sections. Duplicate names are allowed.
- `dw.json`: active values plus `environmentId` and `siteId`; `name` is the selected Site name. Uses **version/cartridgesPath**, not old code-version/cartridges. Preserve unrelated tool-specific keys.
- First workspace folder owns configuration, active file, and Site picker scope; cartridge tree discovery covers the entire workspace. Filesystem APIs assume a local/remote Node extension host, not a browser filesystem.
- Credentials reside in plaintext JSON. No SecretStorage/global credential history UI is implemented in v2.
- Extension identity: `Ferb.dw-manager`. Container: `dwManager`. Views: `dwManagerEnvironmentsView`, `dwManagerSitesView`, `dwManagerCartridgesView`, `dwManagerLogsView`. All commands use `dw-manager.*`; contributed menus and activation events must match registrations.

## Selection and writes

`ConfigStore` tracks pending `environmentId` and `siteId` in memory. Selecting one part writes nothing until the other part refers to an existing record. Selecting either afterward composes it with the retained other selection. Pending partial selection without dw.json persistence is lost when the workspace is reopened.

Creation saves an entry but does not select it automatically. `upsert` replaces by ID, keeps other entries, saves config, and reapplies dw.json only when the edited entry is selected. No lookup by display name is used. `remove` clears matching selection and strips only the deleted ID from active dw.json to prevent reverse reflection resurrecting intentionally deleted records on startup. Other active values remain usable by external tooling until a valid replacement pair is selected.

Writes use same-directory UUID temporary files plus rename so watchers do not observe partial JSON. Config and active writes are sequential, not one transaction. There is no cross-window filesystem lock; concurrent extension hosts editing the same workspace can race.

## Startup and reverse reflection

Activation calls `ConfigManager.initialize()` after registering providers and commands. `ConfigStore.load()`:

1. Reads dw.json (if any) without mutating malformed JSON.
2. Loads and validates dw-manager.json if present.
3. Otherwise migrates dw-envs.json if present, retaining the original; otherwise starts with empty sections in memory.
4. Calls `reflect()` to restore known selected IDs and synchronize complete active values.

When dw.json has both IDs plus all five string fields, `reflectActive` updates the Environment's hostname/user/password/version and the Site's cartridgesPath **by ID**. Saved display names stay unchanged. Missing records are restored under the exact active ID with generated labels; collision with the other section is rejected. Reflection does not match by hostname/name. Incomplete values/ID pairs do not overwrite records, though existing individual IDs can restore one indicator.

`dw.json` is authoritative on open and external reload. Editing the selected Environment/Site through UI takes the opposite direction and updates dw.json immediately. Editing active values directly in dw-manager.json while stale dw.json still references them will be overwritten during reflection; edit the active record through UI or update dw.json as well.

ConfigManager watchers cover the first folder's dw-manager.json and dw.json, debounce 150ms, and compare file text against the remembered post-action state to ignore their own writes. External edits reload into a fresh store; invalid JSON disables the current store until a valid reload. Workspace folder changes reinitialize watchers/store. Disposal clears watcher registrations and pending timer.

## Migration

`migrateLegacy` accepts `{sandboxes:[...]}` with either actual `version/cartridgesPath` fields or older `code-version/cartridges[]`. It creates one Site per legacy entry; Environment records deduplicate only when hostname, username, password, and version all match. Legacy names label new entries; exact cartridge order is retained. IDs are generated once and persisted.

For a legacy active dw.json lacking both IDs, assign the corresponding pair only if exactly one legacy entry matches its name and hostname. Prefer current active version/path values over stale saved values, then reflect them. Preserve extra tool options. Ambiguous/unmatched active data stays untouched until users select a pair. Existing dw-manager.json takes precedence forever; do not regenerate IDs on every startup.

## Prompts and menus

Environment creation/edit prompts for name, hostname, username, masked password, version; cancellation aborts before writes. Site prompts for name and ordered path, allowing empty path. Site cartridge picking merges existing names first and discoveries after them; existing order is preserved and canceled picker is a no-op. Unknown entries fail instead of creating replacements during edit. Delete asks a modal confirmation.

Create/select commands work from the palette. Item-specific edit/delete/cartridge/log commands are hidden from the palette and receive the tree item. TreeItem.id is the persistent record UUID. Labels may repeat. Environment details show ID/host/user/version; Site details show ID/path; never display password in tree tooltips.

## ZIP behavior

Export writes dw-manager-setup.zip with dw-manager.json and optional dw.json, waiting for output close and archive finalize before reporting success. Import reads only exact root config entries via unzipper.Open.file and entry.buffer; it never extracts arbitrary paths. Duplicate root config entries fail. Parse/validate config before workspace writes. Legacy ZIP dw-envs.json is migrated, with active IDs added when uniquely matched. Import triggers manager reinitialization after its promise resolves.

Global credential history backups from v1 are not part of v2's environment/site store. ZIPs contain plaintext credentials. Stream exceptions are reported with generic messages that do not echo file contents. Import replaces files and is not atomic across both configurations.

## Cartridge discovery (unchanged)

Scan workspace .project files with Demandware nature `com.demandware.studio.core.beehiveNature`, excluding node_modules/.git/.vscode. Prefer a project's cartridge/ root; otherwise children in cartridges/ containing cartridge/ or ending in _cartridge; otherwise a _cartridge project or DW project fallback. Merge classic cartridge-folder and _cartridge ancestry matches. Limits: 20,000 project matches and 10,000 fallback matches.

Deduplicate lowercased absolute roots; sort by basename. The optional root filter uses string startsWith rather than a filesystem boundary/realpath check; duplicate basenames are not disambiguated. The directory fallback uses file-oriented workspace.findFiles and should be verified for independent bare-folder support. Tree reads directories synchronously and sorts folders before files. Watchers cover cartridge/**, *_cartridge/**, .project. Open Cartridge replaces the current workspace window via vscode.openFolder, not adding a workspace folder.

## Logs (mostly unchanged)

Read dw.json hostname/username/password to GET https://<host>/on/demandware.servlet/webdav/Sites/Logs/ using Basic auth over TLS. The list parser handles double-quoted .log hrefs, decodes/deduplicates, and sorts descending; it does not normalize arbitrary nested/absolute hrefs. Requests have no explicit timeout.

Session map keys are filenames. Extension-level config changes compare the active credential tuple; a changed tuple disposes previous sessions, while a Site-only change keeps sessions. Output names are SFCC Log: <file>; polling interval 4s, first poll downloads the whole file. UTF-8 byte offsets handle 206 partial content; 200 handles full responses and shorter/rotated files; 416 is treated as no new content.

Remaining tail limitations: overlapping setInterval polls are possible; truncation returning 416 does not reset offset; after an error stop the tree map entry remains; start() can schedule polling after its initial poll caught an error. These are existing limitations, not deliberate retry behavior. Extension disposal and explicit Stop Tailing dispose channels/timers.

## Build and verification

Use Node from .nvmrc (VSCE 4 requires >=22). npm run build -> build:vsix -> local VSCE package --no-dependencies -> vscode:prepublish -> TypeScript compile + esbuild bundle. TypeScript targets ES2019/CommonJS and writes out/; VS Code executes out/extension.js via package.json.main. Edit src/, never generated out/. Runtime archiver/unzipper are bundled; vscode is external; AWS client is external only for unzipper's unused optional S3 helper.

Allowlisted VSIX assets: package.json, out/extension.js, README, LICENSE, icon.png, icon.svg. Configuration files/fixtures (including credentials), AGENTS/AI context, tests, sources, scripts, node_modules, and old VSIX files must stay out. Output is dist/dw-manager-<version>.vsix, ignored by Git.

Tests cover model validation/composition/reflection/migration; filesystem selection, startup, preserving active options, stable migration IDs/deletion; legacy JSON/picker utilities, cartridge discovery, log-list parsing. Run relevant tests and compile for changes; for packaging also inspect the actual ZIP and smoke-test its isolated runtime/registrations. Real remote logs and Prophet still require VS Code/manual testing.
