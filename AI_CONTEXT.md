# DW Manager v2 implementation context

Read `AGENTS.md` for the required version policy, CHANGELOG updates, and documentation completeness rules. Update affected README sections and this implementation map together with each project change. This file maps implemented behavior; verify source and tests when editing. V2 is a major schema/UI change from combined Sandboxes to independent Environments and Sites.

## Contract

- Workspace file: `dw-manager.json`, `{schemaVersion: 2, upload?: UploadSettings, environments: Environment[], sites: Site[]}`.
- Environment: `{id,name,hostname,username,password,version}`, all strings.
- Site: `{id,name,cartridgesPath}`, all strings; path is a colon-separated ordered string, optionally empty.
- IDs generated by `crypto.randomUUID()` on creation; edits/renames retain IDs. IDs must be nonempty strings and unique across both sections. Duplicate names are allowed.
- `dw.json`: active values plus `environmentId` and `siteId`; `name` is the selected Site name. Uses **version/cartridgesPath**, not old code-version/cartridges. Preserve unrelated tool-specific keys.
- First workspace folder owns configuration, active file, and Site picker scope; cartridge tree discovery covers the entire workspace. Filesystem APIs assume a local/remote Node extension host, not a browser filesystem.
- Credentials reside in plaintext JSON. No SecretStorage/global credential history UI is implemented in v2.
- Extension identity: `Ferb.dw-manager`. Container: `dwManager`. Views: `dwManagerEnvironmentsView`, `dwManagerSitesView`, `dwManagerActivitiesView`, `dwManagerLogsView`, `dwManagerImpexView`. All commands use `dw-manager.*`; contributed menus and activation events must match registrations.

## Selection and writes

`ConfigStore` tracks pending `environmentId` and `siteId` in memory. Selecting one part writes nothing until the other part refers to an existing record. Selecting either afterward composes it with the retained other selection. Pending partial selection without dw.json persistence is lost when the workspace is reopened.

Creation saves an entry but does not select it automatically. `upsert` replaces by ID, keeps other entries, saves config, and reapplies dw.json only when the edited entry is selected. No lookup by display name is used. `remove` clears matching selection and strips only the deleted ID from active dw.json to prevent reverse reflection resurrecting intentionally deleted records on startup. Other active values remain usable by external tooling until a valid replacement pair is selected.

Writes use same-directory UUID temporary files plus rename so watchers do not observe partial JSON. Config and active writes are sequential, not one transaction. There is no cross-window filesystem lock; concurrent extension hosts editing the same workspace can race.

## Startup and reverse reflection

Activation calls `ConfigManager.initialize()` after registering providers and commands. `ConfigStore.load()`:

1. Reads dw.json (if any) without mutating malformed JSON.
2. Loads and validates dw-manager.json if present.
3. Otherwise migrates dw-envs.json if present, retaining the original; otherwise starts with empty sections in memory.
4. Calls `reflect()` to restore known selected IDs and synchronize complete active values.

When dw.json has both IDs plus all five string fields, `reflectActive` updates the Environment's hostname/user/password/version and the Site's cartridgesPath **by ID**. Saved display names stay unchanged. Missing records are restored under the exact active ID with generated labels; collision with the other section is rejected. Reflection does not match by hostname/name. Incomplete values/ID pairs do not overwrite records, though existing individual IDs can restore one indicator.

`dw.json` is authoritative on open and external reload. Editing the selected Environment/Site through UI takes the opposite direction and updates dw.json immediately. Editing active values directly in dw-manager.json while stale dw.json still references them will be overwritten during reflection; edit the active record through UI or update dw.json as well.

ConfigManager watchers cover the first folder's dw-manager.json and dw.json, debounce 150ms, and compare file text against the remembered post-action state to ignore their own writes. External edits reload into a fresh store; invalid JSON disables the current store until a valid reload. Workspace folder changes reinitialize watchers/store. Disposal clears watcher registrations and pending timer.

## Migration

`migrateLegacy` accepts `{sandboxes:[...]}` with either actual `version/cartridgesPath` fields or older `code-version/cartridges[]`. It creates one Site per legacy entry; Environment records deduplicate only when hostname, username, password, and version all match. Legacy names label new entries; exact cartridge order is retained. IDs are generated once and persisted.

For a legacy active dw.json lacking both IDs, assign the corresponding pair only if exactly one legacy entry matches its name and hostname. Prefer current active version/path values over stale saved values, then reflect them. Preserve extra tool options. Ambiguous/unmatched active data stays untouched until users select a pair. Existing dw-manager.json takes precedence forever; do not regenerate IDs on every startup.

## Prompts and menus

Environment creation/edit prompts for name, hostname, username, masked password, version; cancellation aborts before writes. Site prompts for name and ordered path, allowing empty path. Site cartridge picking merges existing names first and discoveries after them; existing order is preserved and canceled picker is a no-op. Unknown entries fail instead of creating replacements during edit. Delete asks a modal confirmation.

Create/select commands work from the palette. Item-specific edit/delete/Site-cartridge/log/Impex-file commands are hidden from the palette and receive the tree item. The Site Actions submenu exposes Start Debugging and Enable/Disable Upload; the Sites header also offers Start Debugging. Debugging selects an item's Site, retains or prompts for an Environment, requires Prophet SqrTT.prophet, applies the complete pair and awaits the Activities lifecycle before launching type prophet/request launch. Cancellation of either missing selection prevents launch. Upload enable selects its clicked Site, retains/prompts for an Environment and binds a single workspace uploader; disable disposes its DW Manager watcher/queued work and aborts HTTP requests. Upload All and selected-cartridge variants live in the same Site Actions menu. Activities resumes the saved pair/scope in watch-only mode. Prophet is required only for debugging. ConfigManager pre-write hooks stop upload before changing a managed active pair, and block changes while a debugger target is pending. The removed Cartridges sidebar is not registered and its watchers are not instantiated; legacy cartridge command IDs remain available, with palette pickers for open/reveal and a discovery count for refresh. TreeItem.id is the persistent record UUID. Labels may repeat. Environment details show ID/host/user/version; Site details show ID/path; never display password in tree tooltips.

## ZIP behavior

Export writes dw-manager-setup.zip with dw-manager.json and optional dw.json, waiting for output close and archive finalize before reporting success. Import reads only exact root config entries via unzipper.Open.file and entry.buffer; it never extracts arbitrary paths. Duplicate root config entries fail. Parse/validate config before workspace writes. Legacy ZIP dw-envs.json is migrated, with active IDs added when uniquely matched. Import replaces dw-manager.json; dw.json is replaced only when included in the archive. Otherwise existing active IDs/values remain and are reflected into the imported store on reinitialization. Import triggers manager reinitialization after its promise resolves.

Global credential history backups from v1 are not part of v2's environment/site store. ZIPs contain plaintext credentials. Stream exceptions are reported with generic messages that do not echo file contents. Import replaces files and is not atomic across both configurations.

## Cartridge discovery (unchanged)

Scan workspace .project files with Demandware nature `com.demandware.studio.core.beehiveNature`, excluding node_modules/.git/.vscode. Prefer a project's cartridge/ root; otherwise children in cartridges/ containing cartridge/ or ending in _cartridge; otherwise a _cartridge project or DW project fallback. Merge classic cartridge-folder and _cartridge ancestry matches. Limits: 20,000 project matches and 10,000 fallback matches.

Deduplicate lowercased absolute roots; sort by basename. The optional root filter uses string startsWith rather than a filesystem boundary/realpath check; duplicate basenames are not disambiguated. The directory fallback uses file-oriented workspace.findFiles and should be verified for independent bare-folder support. Tree reads directories synchronously and sorts folders before files. Watchers cover cartridge/**, *_cartridge/**, .project. Open Cartridge replaces the current workspace window via vscode.openFolder, not adding a workspace folder.

## Activities / Prophet lifecycle

The Show Activities command opens the DW Manager container and reveals the stable upload root through the owned TreeView handle. A stale view registry offers Reload Window. Activities is between Sites and Logs; user layout can override default placement.

DW Manager owns one UploadSession per workspace; it no longer enables Prophet's native uploader. This avoids Prophet 1.4.81 cleanOnStart returning true after the first invocation, and its fire-and-forget Enable command hiding cancellation/failure. stopProphetUpload keeps the saved flag false and stops an active native subscription without activating idle Prophet. Startup/reload always leaves DW Manager upload Off; deactivate/dispose aborts requests, timers and watchers. Native Prophet commands called externally are outside this registry.

Upload enable selects the requested Site and retains/prompts for an Environment. Default enable is watch-only with zero initial HTTP requests. uploadCartridgeNames expands nonempty Site paths with an exact modules entry once (never substring matching), without changing Site or dw.json. The picker includes it; explicit selected/resume scopes are not expanded afterward. enableUploadAll does full local-file upload first; enableSelectedUpload and enableSelectedUploadAll ask for one or more cartridges from the Site path. Cancel/empty picker leaves Off. Generation and active fingerprint checks after awaits prevent stale starts. Scope selection does not change Site.cartridgesPath or debug configuration. workspaceState dwManager.uploadBinding contains safe target IDs/labels/hostname/digest plus cartridge names, never credentials. Saved scopes are checked against the current Site on manual resume; resume is always watch-only. Old bindings without scope use all Site cartridges.

UploadSession captures connection values in memory and creates watchers only for resolved roots under the first workspace. Discovery adds the immediate repo/cartridges/name layout, enforces physical boundaries, rejects symlinks and keeps the first valid discovered root per exact cartridge basename, warning/skipping subsequent distinct roots like Prophet. Exact-path repeats are deduplicated silently; requested names are deduplicated too. DuplicateUploadRoot callback captures kept/skipped metadata, and Activities aggregates a warning after stale-target checks, logs retained paths, then starts watchers/ZIPs only for retained roots. SFRA modules roots are recognized by basename modules plus a non-symlink .project containing Demandware nature, without requiring cartridge/. The Company fallback also finds this layout. Resolved UploadCartridge.layout=modules enables root-file filtering in engine and watcher. Missing/unavailable roots invoke a callback and are skipped. Activities aggregates one warning, logs skipped names, and starts only available roots; if none remain, keep Off and send no requests. Save the requested cartridge-name scope for manual resume so missing names are retried on the next start; tooltip/progress use the effective available scope. Watch changes are coalesced per file for upload.watchDebounceMs (default 300ms) and queued with at most N independent operations (N = top-level upload.concurrency, default 5). UploadQueue blocks jobs overlapping an active path or an earlier pending path, preserving same-file and ancestor/descendant order (especially subtree deletes) while unrelated files run together. Directory change jobs retain their subtree lock. Upload All first drains existing watch work, runs N bounded cartridge ZIP workers, and holds a batch barrier for later watcher events; subsequent changes read current local bytes after batch completion. Shared version-validation and directory promises avoid redundant requests. Watch status aggregates completed/total operations and returns Watching only when all burst work finishes. On first task failure dispose queue/client, await worker settlement, then report the original error instead of cancellation. Stop rejects pending jobs and aborts all active HTTPS requests. On first transfer validate the existing code version with PROPFIND Depth 0; do not auto-create/activate a version. Watch creates MKCOL parents then PUT .project or cartridge/** bytes (root-level files/folders for modules); watched DELETE handles local deletions only. Batch deployments archive eligible files with cartridge-prefixed entries, PUT a unique dw-manager-<cartridge>-<UUID>.zip at version root, POST form method=UNZIP, then DELETE only that temporary ZIP. Never delete the remote cartridge before extraction. Hidden paths, configured ignore matches (default node_modules/ and ZIP suffix), symlinks and root configs are excluded. Upload All enumerates only the chosen scope, preserves remote-only files and extra cartridges, and never cleans a remote version. ZIP archives use private mode-0600 temp files and compression level 1, stream to HTTP without whole-archive buffers, and always clean local temp storage. Canceled archive creation aborts output before cleanup; canceled ZIP input streams await close before deleting temp files. ZIP PUT/POST/DELETE retry transient errors up to three times (4/6/8s), preserving the archive and reopening the input stream on each PUT. Retry waits subscribe to session abort and stop immediately. Failed attempts do not dispose the batch until retries exhaust. UploadRequestError includes method/path/allowlisted code, never raw message or credentials. UploadHttpError carries status for retry classification; 401/403, TLS and local errors fail without retry. Best-effort remote cleanup uses UploadClient.cleanupZip with a fresh one-socket client bound to the original target and a 10s inactivity timeout, even after the main client is disposed. Only an engine-owned unique ZIP is removed, with restrictive root filename validation. Cleanup cannot replace the original error; warn only if deletion is not confirmed. It uses a shared HTTPS keep-alive agent with maxSockets/maxFreeSockets=N, direct certificate verification, 60s watch inactivity timeouts and 300s ZIP transfer/extraction inactivity timeouts; Prophet proxy/ignore settings are not consumed. No initial connectivity check or deployment in watch-only mode. Upload All progress title contains Site @ Environment only; its reporter displays completed/total cartridges and increments from engine progress. HTTP/local failures stop the session and show Failed with safe Output summaries, never raw HTTP bodies or stack traces. Cancel batch progress stops the watcher too and shows Off; Stop/dispose aborts requests and clears queued work. Completed server writes cannot be undone. Activities reports Watching/Uploading cartridge counts for batches (file operations for watch bursts)/Starting/Off/Failed; these are our own observed operations, not Prophet byte progress.

UploadOutput is owned by Activities and created lazily at first enable/show. One channel persists across sessions; source inspiration: Prophet providers/Uploader.ts and server/uploadServer.ts at commit 8d9a9a434cf101305d26b0e3ce4c89054f57b351 (MIT). No upstream engine is vendored: locally implemented filtering/warning, Output and configurable bounded file concurrency (default five) behavior; native Prophet is still stopped. Engine logger hooks report watch [U]/[D] operations, cartridge ZIP creation/send/UNZIP/cleanup/completion, validation and batch completion/time; Activities reports target/mode/scope, skip warnings, Cancel/Stop and errors. setTarget redacts username/password/Basic credential token from every emitted line and neutralizes control characters. Never log config objects/headers/HTTP bodies/stacks. showUploadOutput is registered/contributed in palette, Site Actions, Activities header; clicking upload row executes it. Output is shown with preserveFocus=true, disposed with Activities, and no persistent log file is created. Upload Output does not change quiet repo-task logs.

Manager beforeActiveChange hooks guard selection changes, selected record edits, cartridge picking and deletion. Import runs the guard after ZIP validation, before writes. Hooks pause upload before writing; pending debug target blocks managed changes. Same-pair debug can coexist with upload. External reload reconciles upload/pending debug afterward. Repo actions remain independent of these hooks and dw.json.

Debug launch metadata __dwManagerTarget contains IDs/names/hostname; __dwManagerFingerprint is a one-way digest of host/user/password/version. Activities.beforeDebug waits for Prophet debounce and holds a pending guard until matching DebuggerConfig reaches the adapter. registerDebugAdapterTrackerFactory observes onWillReceiveMessage DebuggerConfig (arguments.config), compares digest, stops mismatches; initialized event marks Running. A unique __dwManagerRunId cancels delayed session starts after Stop/timeout; stop any such late session when its tracker is created. Keep each session's pending guard isolated; termination of an older session must not clear a new session's guard. Initialization times out after 30s. Same-host concurrent observed sessions are blocked because Prophet defaults to a shared client ID/breakpoint state; different hosts can coexist. External/debug startup sessions lacking metadata are labeled unverified. Internal protocol was inspected in installed Prophet 1.4.81; no change to Prophet itself. Keep same-host guard: its clientId defaults to prophet and launch clears breakpoints; multiple different-host sessions are allowed and tested at the orchestration layer. Actual simultaneous sandbox debugging still needs manual host verification.

Activities tracks task start/end/process-end plus existing taskExecutions. Definition includes runId/siteId/siteName/rootDir/action; tree children read root .dw-update-log.json and filter run_id. Engine activity_steps stores current-run git/install/compile phases separately from smart-build cached statuses. Stop calls TaskExecution.terminate; rows show Stopping until lifecycle completion. Re-run calls the captured Site/action command, rereading current settings. Completed repository task rows stay in memory until clear/reload; no arbitrary terminal process discovery. No raw command/failure output is collected. Clear Finished preserves running rows. Debug Stop targets one live session. onDidTerminateDebugSession deletes only that session from debugRecords and clears pending state only when its sessionId matches; terminated debug rows are never retained for restart/history. Restart from Sites. Upload toggle targets the single global binding.

## Site repository tools

Config schema remains 2. Optional top-level repoTools and Site.repoTools shallow overrides hold rootDir/nodeVersion/priorityBranches/gitJobs/repoJobs/reinstallDays/skipRepos. Validation rejects invalid settings. Site edits spread existing records to retain overrides. Defaults: Node 8.17.0, priority staging-new/v3.3.0/release/v3.3.0/master, Git 8 workers, repo 4, reinstall 30 days, the user's seven skipped repos. Supplied skipRepos replaces the inherited map.

Commands dw-manager.repos.* operate on a raw read of dw-manager.json and Site ID. Never use ConfigStore.load/select/apply or manager.run for these commands: no selection changes, no dw.json read/write/reflection. Paths default to first workspace root; rootDir may override. Discovery matches immediate non-symlink child Git repos by cartridges/<name>. Preview is read-only; Configure inserts defaults and opens the config; state opens .dw-update-log.json. No environment credentials enter task snapshots. Reset/update/reinstall prompt with concrete repo scope. Task arguments use ProcessExecution (no shell interpolation).

Tasks execute bundled scripts/update-repos.sh with a private temporary snapshot, --root and action. End listeners clean snapshots and report OK/FAIL/stopped. VS Code owns task termination; root lock and atomic/flock state serialize independent runs. Bash and Python 3 are required; Node steps source NVM and use an already-installed configured version. Windows native host is unsupported. Git fetches all refs, verifies remote priority branches, resets/cleans/switches to first existing remote branch, and excludes failed repos from npm. All Git workers finish before any npm step.

Actions git/install/reinstall/compile/scss/js/install-compile/all/changed reuse the original engine. Force install bypasses smart state; reinstall removes node_modules. Compile tasks cache missing scripts by package hash; SCSS/JS-only completion is partial so full builds remain due. Age/Node/dependency hash drive install planning. State is root-shared, schema_version 1, per repo/cartridge, and never stores raw command/error output. Site-config skipRepos is authoritative; legacy script-only mode retains state-file skips and dw.json input. Company standalone script mirrors the packaged engine; keep both aligned when changing engine logic.

Tests must use temporary repositories and stub npm/NVM, never reset/install real user repositories during verification. Cover branch priority/switch, barrier/concurrency, failed sync exclusion, reinstall/cache/skip behavior, chosen Site independence from malformed dw.json, settings preservation and task snapshot/menus/packaging. Cancellation/real NVM and UI behavior also need manual host testing. Known limits: immediate-child layout, NVM required, same root shares state, no per-repo Node versions within one Site, no arbitrary compile commands, and Bash worker cleanup waits on child processes after signals.

## Impex

Uses the active dw.json credentials to browse Sites/Impex/ via HTTPS Basic auth and Depth: 1 PROPFIND. The parser handles namespace prefixes, XML/URL escaping, self responses, successful propstats, child-only filtering and deduplication; directories sort first. Path segments are individually encoded; traversal/absolute paths are rejected. Requests time out after 30 seconds and accept only 2xx responses.

Folder expansion lists children. Text extensions xml/json/txt/log/csv/properties open an untitled editor snapshot, with no remote upload. Other files prompt for a destination and download raw bytes using workspace.fs. Reads/downloads buffer complete files in memory; very large files have no explicit size limit. No remote write/delete or streaming download is implemented.

Manager changes refresh the tree and increment a generation counter to discard stale responses. Items carry a digest of the active credential tuple so old Environment items cannot be opened against the new Environment. Tree data/errors never contain credentials. Real SFCC permissions/server compatibility need manual testing.

## Logs (mostly unchanged)

Read dw.json hostname/username/password to GET https://<host>/on/demandware.servlet/webdav/Sites/Logs/ using Basic auth over TLS. The list parser handles double-quoted .log hrefs, decodes/deduplicates, and sorts descending; it does not normalize arbitrary nested/absolute hrefs. Requests have no explicit timeout.

Session map keys are filenames. Extension-level config changes compare the active credential tuple; a changed tuple disposes previous sessions, while a Site-only change keeps sessions. Output names are SFCC Log: <file>; polling interval 4s, first poll downloads the whole file. UTF-8 byte offsets handle 206 partial content; 200 handles full responses and shorter/rotated files; 416 is treated as no new content.

Remaining tail limitations: overlapping setInterval polls are possible; truncation returning 416 does not reset offset; after an error stop the tree map entry remains; start() can schedule polling after its initial poll caught an error. These are existing limitations, not deliberate retry behavior. Extension disposal and explicit Stop Tailing dispose channels/timers.

Configuration files/fixtures (including credentials), AGENTS/AI context, tests, sources, other scripts, node_modules, and old VSIX files must stay out. Output is dist/dw-manager-<version>.vsix, ignored by Git.

Tests cover model validation/composition/reflection/migration; filesystem selection, startup, preserving active options, stable migration IDs/deletion; legacy JSON/picker utilities, cartridge discovery, log-list parsing, Impex directory parsing/HTTP and binary handling, stale Impex results, and Prophet launch/cancellation behavior. Run relevant tests and compile for changes; for packaging also inspect the actual ZIP and smoke-test its isolated runtime/registrations. Upload tests cover scope/discovery, zero-request watcher start, file transfer/deletion, ignoring configs and symlinks, HTTP failures, cancellation, and activity state. Real remote uploads, logs and Prophet still require VS Code/manual testing.

Activities view lifecycle: createTreeView owns a disposable handle; Show Activities reveals the stable upload root using TreeView.reveal, not the generated .focus command. Provider getParent supports reveal. Register UI/commands before awaited upload reset so a settings/native-command failure cannot prevent view registration. Show offers Reload Window if the workbench still has stale contributed views after extension replacement.

Global upload configuration: optional root `upload: {concurrency?: number, watchDebounceMs?: number, ignore?: string[]}` accepts positive safe integers; omitted fields default to 5. Activities resolves it when enabling, passing the same snapshot through UploadSession to engine watch queue, ZIP workers and HTTPS agent. All Sites share this value, without Site overrides or dw.json synchronization. A running session retains its value until Disable/Enable; config import/export preserves it.

Upload settings also snapshot debounce (default 300ms, nonnegative integer within JS timer range) and ignore regex strings (default node_modules/ and \.zip$, case-insensitive; explicit arrays replace defaults). Compile regex once per engine/session; match normalized cartridge-relative paths and ancestor directory prefixes to exclude descendant watcher events and folder deletes. Apply ignores during enumeration/ZIP creation and watched PUT/DELETE as well. Retain hidden/symlink/scope guards. modules is the explicit root-file layout exception; exclude root dw.json/dw.js/dw-manager.json/dw-envs.json in this layout. ZIP enumeration traverses modules root instead of assuming root/cartridge exists. Upload All status uses cartridge totals in completed/total and cartridgesCompleted/cartridgesTotal; count each after extraction and ZIP cleanup, count empty skipped cartridges complete, and show cartridge counts/percentage in notification and batch Activities. Stage failures include method/path/status with a specific permissions/version/security hint for 403; no raw response text and no automatic permission retries or per-file fallback. Transient network/HTTP failures get three cancellable retries per ZIP stage.

Upload duplicate priority follows valid Demandware `.project` discovery order using Prophet’s folder-scoped `RelativePattern` query (`**/.project`, excluding `**/{node_modules,.git}/**`, without a result cap). The first valid root wins; filesystem search order is not a fixed alphabetical priority. Supplemental DW Manager bare-folder discovery runs afterward and cannot override that root.
